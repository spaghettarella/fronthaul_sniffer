# Release packaging

`make_demo_release` turns the current build into a folder someone else can
unpack and run — no compiler, no `apt install`, no repository clone. Everything
the program needs that is not part of a base Ubuntu install travels with it.

```bash
./release/make_demo_release
```

That produces, next to the script:

```text
fronthaul_sniffer-demo-<version>-<git-rev>-linux-x86_64/       the bundle
fronthaul_sniffer-demo-<version>-<git-rev>-linux-x86_64.tar.gz what you send
```

Around 29 MB, most of it the two demo captures. The tarball and the unpacked
bundle are both gitignored, so building a release never dirties the tree.

The binary comes from `build/` as it stands — the script does not rebuild
unless asked, but it warns when a source file is newer than the binary. Use
`--rebuild` to build first, `--help` for the full option list.

## What the recipient does

```bash
tar -xzf fronthaul_sniffer-demo-<version>-<git-rev>-linux-x86_64.tar.gz
cd fronthaul_sniffer-demo-<version>-<git-rev>-linux-x86_64
./run.sh
```

Then **click the startup screen once** — the configuration panel is behind that
first click — and pick the demo pcap source to replay the bundled capture.
Live capture needs `sudo -E ./run.sh` so the window can still reach the
desktop. The bundle carries its own README with all of this plus the option
list, the zoom/marker controls and a troubleshooting table; it is generated by
the script, so it never drifts from what was actually packaged.

## How the bundling works

Three groups of libraries, split by who is the better source for them:

| Group | Where it goes | Why |
| --- | --- | --- |
| libpcap, GLFW, libibverbs, libnl, libsystemd, … | `lib/` | Not installed by default on Ubuntu; always used from the bundle |
| glibc, libstdc++, libgcc, the ELF loader | `lib/compat/` | Kept out of the default search path and used only as a fallback |
| libGL, libX11, libxcb, libdrm, … | not bundled | Must match the target's GPU driver and running X server |

`run.sh` picks between them by *trying* each arrangement — it runs the binary
with `--help`, which exits before any window is created, and uses the first
arrangement that loads:

1. **native** — bundled `lib/` plus the machine's own glibc and libstdc++
2. **compat** — also bundled libstdc++/libgcc, for a machine whose C++ runtime
   is too old
3. **loader** — run under the bundled ELF loader with the bundled glibc, for a
   machine whose glibc is too old

Native is tried first on purpose: the GL driver is loaded from the target
machine and behaves best alongside that machine's own runtime. Falling back
only when a probe actually fails means no version arithmetic to get wrong, and
a machine that needs nothing special gets a completely ordinary process.
`FH_DEBUG=1 ./run.sh` prints the chosen mode; `FH_LAUNCH_MODE=loader ./run.sh`
forces one.

This build needs glibc 2.38 natively, which is Ubuntu 24.04 or newer — the
fallback is what carries it back to 22.04 and similar. Distributions much older
than that will run out of road eventually, since the system GL stack still has
to be new enough to talk to the bundled GLFW.

Two caveats worth knowing:

- **`setcap` does not work with this bundle.** Granting `CAP_NET_RAW` on the
  binary makes the kernel mark the process as privileged, and it then ignores
  the library paths the bundle depends on. `sudo -E ./run.sh` is the supported
  route for live capture.
- **The bundled glibc is only safe in one direction.** It is newer than the
  target's in every case where the fallback triggers, which is fine. Forcing
  `FH_LAUNCH_MODE=loader` on a machine *newer* than the build host is asking
  for trouble.

## Data files

The program opens its demo captures through paths relative to the working
directory (`../src/capture/demo.pcap`), so the bundle reproduces that layout
and `run.sh` `cd`s into `bin/` before exec. The same directory receives
`imgui.ini`, which is seeded from `build/imgui.ini` so a new user starts with a
sensible window layout rather than a blank one.

`--no-demo-data` leaves the captures out for a ~1.5 MB bundle; demo mode then
needs an explicit `--demo-pcap <path>` and the startup screen loses its
background replay.

## Verifying

The script ends with a smoke test: it runs the packaged `run.sh --help` under
`env -i`, a stripped environment that approximates a machine with none of this
project's build dependencies present. Packaging fails loudly rather than
handing you a bundle that does not start. `--no-verify` skips it.

That test cannot cover the one thing that varies most between machines — the
GL driver — so a real check is unpacking the tarball on a second machine and
watching the waterfall come up.
